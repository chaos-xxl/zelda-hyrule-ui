## 第一块：IP / 版权合规

核心是**「两层权利」的区分**——这是整个合规姿态的地基。

### 第一层：设计素材的著作权 → ✅ 已合规

- 项目的视觉、SVG、UI 结构全部来自 **Hunter Paramore** 在 Figma 社区分享的 **Zelda BOTW UI Kit**。
- 该 Figma 文件是 **CC BY 4.0** 授权——允许商用、修改、再分发（包括以 MIT 这种不同协议发布衍生作品），**唯一要求是署名**。
- 项目已在 `ATTRIBUTION.md` 完整给出署名：作者、网站、原始 Figma 链接、协议、修改说明。**这一层站得住。**

### 第二层：任天堂的商标 + 游戏 IP → ⚠️ CC 管不了，靠姿态处理

- 关键认知：CC BY **只覆盖 Hunter 本人创作的设计表达**，它**没有也不能**授权任天堂的底层 IP——三角力量、希卡之眼、"Zelda"字形等源头是任天堂的商标，不在任何第三方 CC 授权范围内。
- 这层没法靠协议解决，只能靠**定位姿态**：做成「**非官方、非商用的粉丝创作**」，明确声明与任天堂无隶属、收到通知立即配合。

### 落地动作

| 位置 | 内容 |
|------|------|
| README banner | 非官方声明（中英）+ 下游商用风险自负免责 |
| npm package 描述 | "unofficial, non-commercial fan-made..." |
| demo 页脚 | 非官方声明 |
| `ATTRIBUTION.md` | 两层权利澄清 + Trademark Notice + 下游商用免责（中英） |

### 关键边界

- **Logo 不还原官方美术**：`Logo` 组件用「力量三角 + 通用衬线字 ZELDA」替代，**刻意不逐像素还原官方商标 logo**（带 ™ 的注册商标是 IP 红线里最危险的一条）。Figma 的 Logo-Full / Logo-Mark 节点确认不做高精度还原。
- **下游商用风险自负**：MIT 只覆盖代码，不授予任何任天堂商标 / IP 权利。任何人复用（尤其商用）风险自负，IP / 商标侵权责任由使用者承担，与作者无关。

## 第二块：开源协议选择

核心结论：**坚持 MIT，绝不转 AGPL。**

### 起因

想集成归藏（op7418）的两个排版 skill 能力，但归藏是 **AGPL-3.0**（传染性最强的 copyleft）。

### 关键机制：单向兼容

```
MIT 代码  ──可流入──>  AGPL 项目   ✅
AGPL 代码 ──不能流入──> MIT 项目    ❌
```

一旦把归藏的模板 / 版式代码 merge 进仓库，合并成品就被 **AGPL 锁死**——整个项目必须转 AGPL、连部署成网络服务都得交源码。

### 为什么「转 AGPL 对组件库 = 自杀」

- 组件库的价值在于**被广泛 import**。AGPL 传染性 = "用了它的整个产品都得开源"。
- 结果：公司闭源产品、创业者、接活的人——**真正能推它火起来的人全被法务挡在门外**，只剩"个人自己玩不分发"没事，但那部分不带来传播。
- 唯一 KPI 是 **GitHub star**，复盘结论：**license 对 star 的权重 ≈ 0**，转 AGPL 在 star KPI 下**性价比为负**。

### 三条路径取舍

| 路径 | 做法 | 结果 |
|------|------|------|
| **A · 互操作适配层** ⭐ | 不 fork、不拷代码，用户各装各的 skill，只写 100% 原创的「桥接说明」（token 覆盖映射） | ✅ **采用**，AGPL 不传染，保住 MIT |
| B · fork 归藏改主题 | 把它模板改成塞尔达皮 | ❌ 否决，会被迫转 AGPL |
| C · 自建排版系统 | 借鉴**原则**（瑞士设计 / 网格不受版权保护），自己原创一套 | 🔒 远期退路，触发条件未到 |

最终落地 **路径 A**：`skill/references/layout-bridge.md`（骨 + 皮——归藏管"信息怎么排"，本项目管"长什么样"），原则是「学原则、不抄代码」。

### 备查：变更 license 的事实

- 同一项目**可以**变更 license（本项目基本独立开发，无外部贡献者障碍）。
- 变更**不可追溯**：已发布的 MIT 旧版本永久是 MIT，已 fork / 已安装的用户不受影响。
- 但**没必要也不应该**为集成排版能力去转 AGPL。

### 为什么不用「禁止商用」的协议

- OSI 认证的开源协议**没有一个能禁商用**（开源定义第 6 条：不得歧视使用领域）。能禁商用的是 CC BY-NC、BSL 这类——但它们**不算开源**，且 CC 不适合给代码授权。
- 你真正想守的是**"作者自己不靠它赚钱"的姿态**，靠声明 + 行为即可，不需要协议强制。换 NC 类协议反而破坏"开源项目"叙事，对 star 是负向。

## 不做清单（避免重复讨论）

| 决策 | 原因 |
|------|------|
| ❌ 不转 AGPL | star 是唯一 KPI，license 对 star 权重≈0；转 AGPL 性价比为负。坚持 MIT。 |
| ❌ 不 fork 合并归藏代码 | 会触发 AGPL 传染，摧毁组件库的可被采用性。只做互操作（路径 A）。 |
| ❌ 不商业化 | 这是任天堂 IP「粉丝创作」叙事能站住的前提。 |
| ❌ 不还原官方 Logo 美术 | 注册商标（带 ™）是 IP 红线里最危险的一条。用安全替代版。 |
| ❌ 不用 NC 等「禁商用」协议 | 不算开源，破坏传播叙事，对 star 负向。 |

## 被质疑时怎么回应（话术速查）

| 质疑 | 回应要点 |
|------|---------|
| "这侵权了吧？" | 视觉素材基于 CC BY 4.0 的 Figma 社区文件，已署名；项目是非官方非商用粉丝创作；任天堂权利方有顾虑可提 issue，立即配合。 |
| "MIT 不是能商用吗，那不就侵权了？" | MIT 只覆盖代码，不授予任天堂 IP 权利。代码可自由用，但涉及塞尔达 IP 的商用风险由使用者自负，与作者无关。 |
| "为什么不像归藏一样用 AGPL？" | 组件库靠被广泛 import 才有价值，AGPL 传染性会把企业用户挡在门外；保持 MIT 才利于传播。 |
| "你赚钱了吗？" | 纯爱好项目，作者不靠它赚钱，不商业化。 |
